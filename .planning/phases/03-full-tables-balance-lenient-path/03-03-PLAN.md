<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ZIP bytes → 10 catalogued table reads | Each table read goes through read_table_raw() with ContaPlusReadError wrapping at the reader boundary |
| lenient path → problems collection | Problems list accumulates errors; the errors are structured (ContaPlusReadError), never raw exception messages leaked to user without structuring |
| uncatalogued .dbf scan | diario_path.parent.iterdir() — safe filesystem iteration within the already-extracted tmp directory; _safe_extract_zip() from Phase 2 already prevents path traversal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Tampering | 10-table catalogue single-pass — new DBF readers call read_table_raw() | mitigate | read_table_raw() wraps all reader errors in ContaPlusReadError (Phase 2 established pattern); no change to error boundary |
| T-03-08 | Tampering | Lenient mode D-03 — corrupt DIARIO produces ProblemEntry and continues | mitigate | The outer try/except catches ContaPlusReadError from _read_dbf_path(); file-level journal failures are captured as a single ProblemEntry; test_lenient_corrupt_journal verifies this behavior |
| T-03-09 | Information Disclosure | ProblemEntry.reason contains exc.message from ContaPlusReadError | accept | ContaPlusReadError.message is program-generated text describing field/row context; no raw OS error messages are forwarded; original exception is stored in exc.original but not in the reason string |
| T-03-10 | Denial of Service | Large archive with many uncatalogued .dbf files flooding problems list | accept | Uncatalogued scan produces one entry per file; archive size is bounded by the ZIP decompression bomb guard from Phase 2 (_safe_extract_zip); entry count is proportional to archive content |
| T-03-11 | Tampering | Path traversal in uncatalogued .dbf scan | mitigate | Scan iterates diario_path.parent.iterdir() (already-extracted safe path); no user-controlled path is used; Phase 2 _safe_extract_zip() already guards against zip-slip before this code runs |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in Phase 3 |
</threat_model>
