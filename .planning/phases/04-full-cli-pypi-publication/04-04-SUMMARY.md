## Deviations from Plan

**1. Repo owner changed from `marcfargas` to the `chispa-sideral` org** (maintainer instruction). `pyproject.toml` `[project.urls]` updated accordingly (`119b484`).

**2. Staged execution with a workflow_dispatch path.** The maintainer wanted repo + CI verified, then TestPyPI, then real PyPI — in stages. `release.yml` was extended with a `workflow_dispatch` trigger; the `testpypi` job is gated to dispatch runs and the `pypi`/`micropip-smoke` jobs to real release events (`cf91efa`, `40b1aa9`). This made the D-05 TestPyPI dry-run a clean independent run and avoided a duplicate-version upload conflict on the real release.

**3. A test CI workflow was added** (`ci.yml`) — not in the original plan. The maintainer asked for CI/CD to be verifiable before PyPI; the only planned workflow (`release.yml`) is the publish pipeline and never runs on push. `ci.yml` fills that gap.

**4. `allow_zero_version = true` added to `[tool.semantic_release]`.** PSR defaults `allow_zero_version=False`, which would have forced the first release to `1.0.0`, contradicting locked decision D-04 (first version `0.1.0`). Fix committed in `464bcf9`.

**5. PSR changelog config table corrected.** `changelog_file` was under `[tool.semantic_release]` where PSR v10 ignores it; moved into `[tool.semantic_release.changelog.default_templates]` (`358290d`).

**6. A `v0.0.0` baseline tag** was created at the repo root commit so PSR had a starting point for version computation.

**7. Inline / subagent execution.** Plan 04-04 was executed by the orchestrator and helper subagents rather than a single gsd-executor run, because two earlier gsd-executor subagents on Plan 04-02 were terminated by a content-filter block on their return message.

## Issues Encountered

- PSR initially computed `1.0.0` (the `allow_zero_version` default) — caught by the mandatory `semantic-release version --print` dry-run before the real run; fixed before any publish.
- On Windows, PSR mangles non-ASCII changelog characters unless `PYTHONUTF8=1` is set; the committed `CHANGELOG.md` is clean UTF-8. The CI release path is unaffected (Linux).
