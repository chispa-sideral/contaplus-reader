<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → CLI positional args | `input_file` is a user-supplied path; `output_file` is the write destination |
| CLI → read() | CLI passes file bytes; same untrusted binary input boundary as Plan 01 |
| render_journal → BytesIO | In-memory XLSX generation; no filesystem write until CLI calls output_file.write_bytes() |
| output_file.write_bytes() | CLI writes exactly to the path the user specified; no path derivation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `cli.py` — output path traversal (e.g., `../../etc/cron.d/evil`) | accept | CLI uses `typer.Argument(Path)` which does no canonicalization, but writes only to the exact supplied path with `write_bytes()`. Risk is user-controlled: they specified the path. No auto-derived paths. |
| T-02-02 | Tampering | `cli.py` — silent overwrite of existing critical files | mitigate | `if output_file.exists() and not force:` guard per D-15; exits 1 with error message. Clobber requires explicit `--force` or `--overwrite`. |
| T-02-03 | Information Disclosure | `cli.py` — Python traceback in error output reveals internals | mitigate | `raise typer.Exit(1) from None` suppresses traceback per D-17; only structured Rich panel content surfaced |
| T-02-04 | Tampering | `xlsx.py` — malformed JournalRow values passed to openpyxl | accept | All JournalRow values are validated at reader boundary (Plan 01) before reaching xlsx.py; frozen dataclass prevents mutation after construction |
| T-02-05 | Denial of Service | `xlsx.py` — very large journal (millions of rows) causes OOM in Workbook | accept | CLI is a batch conversion tool; user controls input size. Mitigation requires streaming XLSX write (not in openpyxl's scope for Phase 1). Documented as a large-file limitation. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | Same as T-01-SC: all packages `[ASSUMED]` per RESEARCH.md audit; no new packages added in this plan |
</threat_model>
